## 决策 1：训练集口径 `--pit` 是否设为默认

**事实（实测，`lowturnover_bt.prepare`，test 2021-01→2026-11）**

| 配置 | 快照口径 | 点对点口径 |
|---|---|---|
| 120 只 / 60 树 / h=1 | IC +0.0013（t **0.31**） | IC +0.0149（t **4.11**） |
| 120 只 / 60 树 / h=5 | IC +0.0112（t 2.62） | IC +0.0267（t 7.17） |
| **300 只 / 250 树 / h=5** | IC **+0.0194**（t **5.37**） | IC **+0.0284**（t **9.43**） |

用「训练截止那天的成分」选历史样本 = 用未来成分选过去股票。点对点把 2008–2019
曾入选的 **748 只**都算进来（快照只有 300，漏 60%）。

**选项**

| | 做法 | 代价 | 适合 |
|---|---|---|---|
| **A** | 切默认：`APB_TRAIN_PIT=1` | 训练集 300→748 只，训练时间约 **+60%**；模型一次性重训 | 认这条证据、要 IC |
| **B**（当前） | 保持快照默认，`--pit` 手动开 | 线上模型维持现状（t 5.37 也还行） | 想再要一轮独立复核 |
| **C** | 双轨：训练机两套都跑，按 holdout IC 择优上架 | 训练成本 ×2，但不用预先押宝 | 稳健派 |

**我的建议：C → 然后落 A。** 理由：单次运行、单一种子，虽然两套配置方向一致，
但「+46% IC」这种量级的结论值得再验一次再切默认。

**怎么切**（已就绪，无需改代码）：
```bash
APB_TRAIN_PIT=1 python -m qcore.live_model --train --horizon=5      # 点对点训练
APB_TRAIN_PIT=0 python -m qcore.live_model --train --horizon=5      # 回滚快照
```
**回滚**：把环境变量改回 0，用上一次的 `data/model/versions/` 快照覆盖即可
（`model_transfer` 有版本快照，`--admission` 会拦下"更旧的模型"）。

## 决策 2：模拟盘成交价口径

**事实**

| | 回测 | 模拟盘 |
|---|---|---|
| 成交价 | **T+1 开盘** | **T 日收盘**（或盘中实时价） |
| 口径差 | — | 池内 **+15.95 bps/笔**、当日 top-10 名单 **+71.25 bps/笔** |

往返成本 19.28 bps —— 也就是说名单越集中，模拟盘被"收盘成交"抬得越明显。
现已可观测：`qcore/fill_audit.py` 逐笔记 `gap_bps`，落 `data/state/fill_audit.json`，
`GET /api/fill_audit` 可读（当前 13 笔可归因，均值 +110 bps，`insufficient=true`）。

**选项**

| | 做法 | 代价 | 适合 |
|---|---|---|---|
| **A** | 接受口径差，UI/API 明确标注「模拟盘=收盘、回测=次日开盘」 | 零成本；但两个净值永远不能直接比 | 只把模拟盘当"方向参考" |
| **B** | 改次日开盘成交 + **一次性重算历史净值** | 要写 pending-fill 机制；历史净值断点 | 要"模拟盘≈回测"的严格可比 |
| **C** | 双账本：保留 `close` 账，新增 `next_open` 账并行跑 | 状态翻倍；两套净值各自记账 | 既想留历史又想要新口径 |

**我的建议：A 先落地（已基本做完），把 B 排到下次"净值重算"窗口。**
理由：B 的收益是"可比性"，但它不改变策略有没有 alpha；而 A 的代价是零。

**A 还差的一步**（我可以马上做，约 20 行）：在模拟盘页加一行口径标注 +
把 `/api/fill_audit` 的 `mean_gap_bps` 显示出来。

## 决策 3：四本账是否收敛为统一 prediction store（R50）

**事实**：目前预测分散在四处 —— 主台账 `data/pred_ledger/{year}.jsonl`、
`picks*.json`、`paper/trades.jsonl`、`data/claims/`。同一个"预测"在四处各有一份，
口径靠人记。R48 已把状态层（预热/缓存/游标）摸清。

**选项**

| | 做法 | 代价 |
|---|---|---|
| **A** | 现在做：新增统一 store，四本账写穿到一处 | 状态迁移 + 双写期，约 1–2 轮工作量 |
