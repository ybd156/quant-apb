# 踩坑记录 —— 这一版（v0.20→v0.21）的工程教训

> 这份文件记录**真实发生过的 bug、根因、以及怎么防**。
> 不是设计文档，是事故报告。每条都对应一次用户截图报错或我自测发现的问题。
>
> 按「根因类型」分组，比按时间顺序更有用 —— 同类问题会重复出现。

## 一、共享状态：两个模块写同一个文件/字段，谁也没管对方

**这是本版最高频的 bug 类型，占全部严重问题的 60%。**

### 1.1 跨市场串仓：美股账户用 A 股 picks 下单

| | |
|---|---|
| **症状** | 「1 周 中线」账户净值 500 元，买了 600438/601058/002625/601229 各 1-3 股 |
| **根因** | `paper_auto.rebalance(market="US")` 读的是 `picks_h5.json` —— 那是 A 股的预测。然后用 500 美元本金 + 美股 lot=1，买入了 A 股代码 |
| **为什么没发现** | `predict()` 写 picks 时没写 `market` 字段，`rebalance()` 也没校验。两边各自都"正常" |
| **后果** | 净值、成本、对账全部失真。而且交易记录混在同一个 `trades.jsonl` 里 |
| **修法** | ① `predict` 写 `market`；② `rebalance` 校验 market 匹配；③ picks 没写 market 时用代码形态反查（6 位数字=A股 / .HK=港股 / 纯字母=美股） |
| **防护** | 凡是"一份数据被多个账户共享"，必须在数据里带**归属标识**，接收方必须校验 |

### 1.2 events.json 被覆盖，实时事件反复丢失

| | |
|---|---|
| **症状** | 页面上 2026 年政策事件是空的；重算一次 impact 后 `live` 段消失 |
| **根因** | `policy_calendar.to_state_json()` 直接覆盖整个文件，不保留 `news_live.merge_into_events()` 写的内容 |
| **为什么没发现** | 两个模块单独测都正常，只有按特定顺序跑（先 merge 再 to_state_json）才出问题 |
| **修法** | 写入前读旧文件，保留 `live` / `live_meta` |
| **防护** | 同一文件多写入方时，写入必须**读-改-写**，不能直接覆盖 |

### 1.3 模型文件互相覆盖

| | |
|---|---|
| **症状** | 训练 h=5 后，h=1 的 `gbdt.pkl` 消失了 |
| **根因** | `train()` 里 `save_model(model, meta)` 没传 `horizon`，默认写 h=1 的路径 |
| **修法** | `save_model(model, meta, horizon=h)`，路径按 horizon 分开 |
| **防护** | 任何"多实例"的东西（模型/账户/台账），文件名必须带实例标识 |

## 二、脚本生成：转义把路径改坏了

### 2.1 `\t` / `\b` 被转成控制字符

| | |
|---|---|
| **症状** | `can't find '__main__' module in 'D:\apb-train-kit\tools'` |
| **根因** | 用 Python 生成 bat 时写了 `"tools\\train_one_click.py"`，某环节当成 `"tools\train_one_click.py"`，`\t` → 0x09 制表符。python 收到的参数是目录 `tools` |
| **同类** | `"tools\bootstrap.ps1"` 的 `\b` → 退格符 0x08 |
| **为什么反复犯** | 三次都是「用 Python 字符串拼 Windows 路径」，三次都栽 |
| **修法** | 按字节定位替换，写完立即断言 |
| **防护（必须执行）** | 生成 .bat / .ps1 后的三条断言：<br>① 全部字节 < 0x80（纯 ASCII）<br>② 含 `\r\n`（Windows 换行）<br>③ **不含 0x00-0x08 / 0x0b / 0x0c**（控制字符）<br>然后打印关键行人工核对 |

### 2.2 PowerShell 5.1 按 ANSI 读脚本，中文全乱

| | |
|---|---|
| **症状** | `报假的「缺 }」语法错误`，实际文件语法正确 |
| **根因** | PS 5.1 读 .ps1 时若无 UTF-8 BOM，按系统 ANSI（GBK）解析，中文变成乱码字节，把引号/括号结构破坏 |
| **修法** | 整个 .ps1 改成纯 ASCII（消息用英文） |
| **防护** | 同上：生成后断言纯 ASCII |

### 2.3 `$ErrorActionPreference='Stop'` 让原生命令的 stderr 变致命

| | |
|---|---|
| **症状** | bootstrap 脚本在 `python -m pip --version` 处崩溃 |
| **根因** | 没装 pip 时 python 往 stderr 写 `No module named pip`，在 `Stop` 模式下被当成 terminating exception |
| **修法** | 加 `Invoke-Py` 包装，内部临时把 EAP 降到 `Continue` |
| **防护** | PS 里调原生 exe 一律走包装函数，不直接 `&` |

## 三、数据接错：后端有数据，前端读法不对

### 3.1 数据源健康度把 JSON 键当成数据源

| | |
|---|---|
| **症状** | "源"列显示 `as_of` / `sources` / `summary` |
| **根因** | 真实结构是 `{as_of, sources:{...}, summary}`，UI 用 `Object.keys(sh)` 遍历顶层 |
| **修法** | 遍历 `sh.sources`，加「用途」列 |
| **防护** | 嵌套结构必须**下钻到实际数据层**，不能遍历顶层 |

### 3.2 台账「只有一天」

| | |
|---|---|
| **症状** | 31 个交易日的数据，页面只显示 10-29 |
| **根因** | `rows.slice(0, 500)` 硬截断 + 按日期降序 + 每天 100 行 = 第一页正好是最新一天 |
| **修法** | 加分页 + 顶部日期分布条（柱高=条数，点击筛选那天） |
| **防护** | 任何列表都不做静默截断；超过一屏的必须**让用户看见总量和分布** |

### 3.3 `impact` 表永远是空的

| | |
|---|---|
| **症状** | 「影响因子表」显示"暂无" |
| **根因** | `impact.compute()` 只在完整 pipeline 里调，NAS 上从没跑过 pipeline |
| **修法** | 单独跑一次，得到 9 组，写进 events.json |
| **防护** | UI 展示的字段，必须确认**有代码路径会写它**，否则就是不存在的功能 |

### 3.4 交易原因显示英文 key

| | |
|---|---|
| **症状** | `rebalance_in` 直接显示给用户 |
| **修法** | `reasonText()` 映射表，未知 key 原样显示（不吞信息） |

## 四、样本量：把噪音当信号

### 4.1 阈值扫描里 2 次样本给出 +66bps

| | |
|---|---|
| **症状** | 扫描报告"最优：阈值 0.65 单边做多 +66.89bps/次" |
| **真相** | 那档只有 **2 笔**交易。+66bps 是运气 |
| **同类** | 第一版分钟级评估用训练集评自己，命中率 59.9%（虚高 10pp+） |
| **修法** | ① `MIN_TRADES=30`，不足标 `insufficient` 不参与最优选择<br>② 评估必须**按时间切分**（前 75% 训练 / 后 25% 评估） |
| **防护** | 任何"最优 X"的结论，必须同时报告**样本数**。样本 < 30 一律标"观察，不作结论" |

## 五、"做了但没验证到底"

### 5.1 模型导入接口从来没成功过

| | |
|---|---|
| **症状** | `/api/model/import` 一直 400 |
| **根因** | `MAX_BODY_BYTES = 64KB`，但模型 zip 67KB → base64 后 89KB |
| **为什么没发现** | 写代码时觉得"64KB 够用了"，没实际传一次 |
| **修法** | 提到 16MB |
| **防护** | 每个接口**至少手工调一次**，不能只看代码"应该能行" |

### 5.2 `dist/models` 目录导致发版失败两次

| | |
|---|---|
| **症状** | CI release job 失败：`read dist/models: is a directory` |
| **根因** | `train_one_click.py` 把产物写到 `dist/models/`，`git add -A` 误提交；CI 的 `gh release create dist/*` 把目录当附件 |
| **为什么两次** | 第一次修了 CI 的 `dist/*` → `find -type f`，但没清仓库里的目录 |
| **修法** | ① `.gitignore` 加 `dist/`；② `git rm --cached dist`；③ CI 只传 `find -maxdepth 1 -type f` |
| **防护** | 运行期产物目录必须进 `.gitignore`；发版前检查 `git ls-files` 有无不该提交的东西 |

### 5.3 字符串替换没匹配上，但 `ast.parse` 通过

| | |
|---|---|
| **症状** | 改了"实时上传"逻辑，跑起来还是老流程 |
| **根因** | 替换的目标字符串里是 `-` 不是 `·`，没匹配上；脚本没 assert |
| **同类** | UI patch 静默失败，留下引用未定义变量的死代码 |
| **修法** | 所有替换加 `assert old in s`，失败立刻报错 |
| **防护** | 语法检查通过 ≠ 逻辑生效。**改完必须看实际运行输出** |

## 六、因果红线（这个错了最严重）

### 6.1 盘前信号用当天数据复盘

| | |
|---|---|
| **症状** | `postclose` 拿 11-06 的盘前信号对 11-06 自己的涨跌 |
| **根因** | 信号就是从 11-06 数据算出来的，等于用当天评价当天 |
| **修法** | 加守卫：只有 `data_date > premarket_data_date` 才复盘 |
| **防护** | 任何"评价预测"的地方，先问：评价用的数据，在预测时存在吗？ |

### 6.2 盘中训练的正确形态

用户提出的关键洞察解决了这个困境：
```
T 分钟：用 ≤T 的信息预测 T+3 的涨跌
T+3 分钟：收益已经知道了 → 立刻对账
```
分钟级不存在"不知道收盘结果"的问题，因为标签窗口很短。

## 七、UI 层

### 7.1 浏览器缓存导致"代码改了页面没变"

| | |
|---|---|
| **症状** | 三次以为是代码问题，其实都是浏览器拿的旧 JS |
| **修法** | `index.html` 里 css/js 加 `?v=<版本号>`，server 返回时替换占位符 |
| **防护** | 静态资源一律带版本号；`Cache-Control: no-cache` 不够（有些代理仍缓存） |

### 7.2 `[hidden]` 被作者 CSS 覆盖

| | |
|---|---|
| **症状** | 弹窗不该显示却一直显示 |
| **修法** | 全局 `[hidden] { display: none !important; }` |
| **防护** | 自定义 `display` 的类，必须显式处理 `[hidden]` 状态 |

### 7.3 `if (id === 'paper') { ...; return; }` 阻断后续绑定

| | |
|---|---|
| **症状** | 实盘成交表单（`#trade-form`）永远绑不上事件 |
| **根因** | 新加的事件块以 `return` 结尾，后面同 id 的块执行不到 |
| **修法** | 合并进同一个块，不单独 return |
| **防护** | `bindPageEvents` 里一个 page 只允许**一个** `if` 块 |

## 九、一句话总结

> **本版 90% 的 bug 不是算法错，是接线错。**
>
> 算法部分（Alpha158 / GBDT / HAC / 归因）几乎没出错 —— 因为有测试、有不变量、有样本外验证。
>
> 出错的全是"模块之间的约定"：谁写哪个字段、谁读哪个文件、单位是什么、
> 有没有带标识、样本够不够。这些东西**没有测试保护**，全靠人工核对。
>
> 所以检查清单比代码更重要。

## 十、验证工具本身失灵（本版最严重）

### 10.1 冒烟测试对着报错页面报「通过」

| | |
|---|---|
| **症状** | 页面明明显示「渲染失败 · Cannot access 'x' before initialization」，`scripts/smoke_pages.py` 却报 13/13 全过 |
| **根因** | `subprocess.run(cmd, capture_output=True, text=True)` 在 Windows 用 **locale 编码（GBK）** 解码子进程输出，而 Chrome 输出的是 **UTF-8**。`"页面渲染出错" in dom` 因为 dom 全是乱码而永远为 False |
| **为什么危险** | 它给了我**虚假的安全感**。我基于"13/13 通过"告诉用户"页面没问题"，然后用户一打开就看到报错 |
| **修法** | ① `encoding="utf-8"` 显式指定<br>② 加结构判据 `<h2>渲染失败</h2>`，即使关键字被编码搞坏也能抓到 |
| **验证修法有效** | 对**当前有 bug 的部署**跑一次，确认它真的报 `[FAIL] #events`；再部署修复，确认 13/13 |

**教训：写完检测工具，一定要拿一个「已知会失败」的样本喂给它，确认它真的会失败。**

只验证"通过的情况"等于没验证。

### 10.2 同类：preflight 的 403 假红

`check_http` 用 `dict(os.environ)` 起本地实例，我在命令行设的 `APB_TOKEN`
泄漏进去 → POST 被 `_write_allowed` 拦成 403 → 两个检查全红。

不是代码坏了，是**测试环境没隔离**。

## 十一、长函数里 `const` 的暂时性死区

| | |
|---|---|
| **症状** | `Cannot access 'curatedUntil' before initialization` |
| **根因** | 合并时间线时，`curatedUntil` 的定义写在 `setSub()` 使用它之后。<br>`const` 有 TDZ（暂时性死区），先用后定义直接抛 ReferenceError |
| **为什么 `node --check` 查不出** | 语法完全合法。TDZ 是**运行时**错误 |
| **修法** | 定义提到使用之前；并断言 `s.count('const curatedUntil') == 1` 确认没重复定义 |
| **防护** | 长函数（>100 行）里，所有 `const` 尽量集中在开头；或者改 `let` 并给初值 |

## 十二、替换代码前必须读上下文

| | |
|---|---|
| **症状** | `r is not defined` |
| **根因** | 我给时间线条目插「实时」标签时写了 `(r._live ? ...)`，<br>但 `timeline()` 的 map 回调参数是 **`e`** 不是 `r` |
| **为什么犯** | 文件里别处是 `rows.map((r) => ...)`，我下意识搬了 `r` 过来 |
| **修法** | 改成 `e._live` |
| **防护（必须执行）** | 插入/替换代码前，**先读目标位置往上 5 行**，确认变量名、作用域、是否在回调内部 |
