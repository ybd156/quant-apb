## 三、明确的取舍结论

**抄设计，不抄依赖。** 本项目坚持 numpy + pandas 两条依赖，理由是目标运行环境
（小主机 / NAS）装不了编译栈。因此：

- ✅ 抄：端点、字段口径、词典结构、中性化做法、评估输出格式
- ❌ 不抄：框架依赖（akshare / polars / talib）、并发模型、存储层

**下一步最该做的三件事**（按性价比）：
1. 从股吧爬虫项目里核对**稳定端点**，替掉脆弱的 HTML 正则。
2. 给情绪词典加**否定词与程度副词**（"不涨""暴跌"当前会误判）。
3. 给 amihud 因子加**行业 + 市值中性化**，再测一次增量 IC——这是最可能出真 alpha 的一步。

---

## 四、如何验证"抄来的东西"确实更好

不许因为"大项目这么做"就采纳。每个借鉴都要过同一道门：

```
1. 用本项目数据跑一遍 → 得到 IC 与 HAC t
2. 与现有实现对比 → 增量是否显著（配对检验）
3. 是否通过 Deflated Sharpe（多重检验校正）
4. 是否改变结论方向（如果只是数字好看一点，不值得加复杂度）
```

**没有通过这四步的"优化"，一律不合入。**
